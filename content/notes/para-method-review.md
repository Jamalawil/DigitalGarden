# PARA After Two Years

PARA — Projects, Areas, Resources, Archive — is Tiago Forte's system for organising digital information. The core claim is that information should be organised by actionability rather than by subject. Instead of filing a note about climate change under "Climate," you file it under the project where you will use it.

I have been using a modified version of PARA in my Obsidian vault for two years. My verdict: the framework is genuinely good, the implementation details matter enormously, and the evangelism overstates the case.

## What Works

**Projects as a forcing function.** Having a clear list of active projects — things with a defined outcome and a deadline — is clarifying in itself. PARA forces you to articulate what you are actually working on, as opposed to what you intend to work on.

**The Archive.** The permission to archive rather than delete is underrated. Most information organisation systems fail because people are reluctant to throw things away. PARA's answer — put it in the archive, search it if you need it — is psychologically liberating.

**Reducing friction at capture.** The rule of thumb that information should be captured in the project where it will be used first means you spend less time deciding where things go. Ruthless pragmatism about location.

## What Doesn't Work (For Me)

**Research notes cross project boundaries.** A note about acoustic ecology belongs to the Eremocene project, the documentary project, and the general ecology resource folder simultaneously. PARA's answer is to put it where you'll use it first, but for long-form research this is often underdetermined.

**The system requires active maintenance.** Projects need to be closed and archived as they complete. Areas need to be reviewed. This maintenance overhead is real and is underacknowledged in the PARA literature.

**It's better for execution than exploration.** PARA optimises for getting things done. If your relationship with information is exploratory — following ideas for their own sake rather than in service of a project — the system fights against you.

## My Modifications

I use PARA for my work files (Funnelithic, MARKA, Polymath Review projects) and a separate Zettelkasten-inspired structure for my research notes (the Slipbox, in Obsidian's terminology). The two systems are connected by links but governed by different logics. This is messier than pure PARA but closer to how I actually think.
